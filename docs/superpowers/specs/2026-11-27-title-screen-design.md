# 首页重做：3A 风格开场动画 + 主菜单（设计稿）

日期：2026-11-27　分支：`claude/wonderful-thompson-olaaxb`

## 1. 为什么做、要什么

用户原话：「重新重构整个页面，不要按照之前的布局……把它当作一个全新的游戏，重新设计封面和首页，要像那种 3A 大作的封面一样」「需要有一个完整、超级帅的视频类动画展现，可以用 threeJS 展示」。

一句话：网站一打开，先读一条进度条，然后播一段 Three.js 实时渲染的电影级开场（丧尸围城那一夜），收在 Logo 落下、主菜单浮出。整个网站的气质从「园区导览 + 几个入口」变成「一款叫《围城》的游戏」。

### 目标
- 第一眼就是 3A 游戏标题画面的质感：电影调色、宽银幕黑边、体积光、雨雾、剪影，而不是模拟经营游戏的样子。
- 开场全程不卡顿；主菜单出来后操作流畅（用户：「渲染完读完进度条再进游戏主菜单，不然影响菜单体验感」）。
- 手机能打开、不爆内存（之前几轮用户多次在意手机内存）。
- 主菜单直达所有现有玩法；联机入口照常可用。

### 不做（非目标）
- 不再保留旧的四套封面方案（a/b/c/d）、`?cover=` 切换条，也不参考它们的布局。
- 不改游戏本身（零点突围、丧尸围城、联机、园区导览、小游戏的玩法和进入后的画面都不动）。
- 网站开场不用预渲染视频文件（视频只单独导出给用户看 / 宣传用，见 §8）。

### 反目标（做出来也算失败的情况）
- 看起来像「AI 生成的网页卡片」：带边框的信息卡、NEW 标签、编造的数字（延迟、版本更新新闻）。用户已明确否掉试做版右下角那个框。
- 开场时近景里出现一眼就是方块 / 球体的东西。
- 首页就把整个园区读进内存（手机爆内存）。
- 第二次打开还要被迫看完 26 秒。

## 3. 考虑过的做法

- **A. 用完整园区场景拍**：代入感最强，但要先读完整个园区（80 多 MB 打包）才能开播，手机爆内存；模型偏简洁，近景露馅。否掉。
- **B. 纯手工的独立开场场景**：最快、最省、最容易出质感，但和游戏里的东西对不上，像宣传片。
- **C. B 的轻量场景 + 游戏里现成的模型（用户选的）**：几秒开播、手机安全；画面里出现的都是游戏里真有的东西。

## 4. 页面流程

```
打开网站
  └─ 进度条（黑底，底边细线 + 一句文案，如「正在封锁云澜……」）
       读：开场场景代码、模型、丧尸贴图、字体；建场景；预编译所有着色器；预热几帧
  └─ 开场动画（约 26 秒，任意键 / 点屏幕跳到 Logo）
       镜头 1 高空俯冲 → 2 商场门口尸潮 → 3 楼顶重机枪 → 4 直升机升起、探照灯扫进镜头、白闪
  └─ Logo 落下 → 主菜单浮出（背景是开场场景继续实时循环：楼顶 + 直升机悬停 + 雨）
       同时后台只「下载」游戏文件进浏览器缓存，不解析、不建场景
  └─ 选一个模式 → 「进入关卡」进度条 → 彻底释放开场场景（GL 上下文、贴图、几何体）→ 现有 startRuntime
```

- **第二次打开**（本机记过已看完一次）：进度条后只播短版（约 6 秒：楼顶 + 直升机升起 + Logo），同样可跳过。菜单「设置」里可以「重看开场」。
- **深链**（`?siege=1`、`?room=CODE`、`?play=drone` 等，邀请链接属于这类）：不播开场，直接进对应模式（联机邀请链接要尽快进大厅）。现有 `launchCleanup` / `mergeLaunchQuery` 的地址栏行为保留。
- **系统设置「减少动态效果」**：跳过开场，直接显示静态 Logo + 菜单（背景是一帧定格）。
- 进度条阶段失败（WebGL 不可用、资源 404）：退回一张静态主视觉图（用开场镜头 4 的截图离线做好）+ 同一套菜单，照样能进游戏。

## 5. 主菜单

左上 Logo，左下竖排菜单（选中项红色高亮条 + 下方一句说明），底边一行小字。参考截图：`cover7/shots/title-v2-logoB-r2-34.png`（改过右下角那版）。

一级菜单（顺序即优先级）：
1. 丧尸围城（单人）→ `jimao`，`siege=1`
2. 联机 · 三人 → `jimao`，`siege=1&mp=1`（打开联机大厅）
3. 零点突围 → `jimao`，`siege=0`
4. 园区漫游 → `tour`
5. 更多玩法 → 二级菜单：无人机送外卖（`tour`，`play=drone`）、夜间潜入（`tour`，`play=heist`），显示已有星数（`arcade/progress.js`）
6. 设置 → 二级面板：画质（沿用 `COVER_TIERS` 五档与 `readCoverTier/writeCoverTier`）、开场（总是播完整版 / 短版 / 不播）、音量（若有音频，见 §7）、重看开场

- 键盘上下 + 回车、手柄式焦点；鼠标悬停；手机点按。Esc 返回上一级。
- 底边：左边按键提示（确认 / 返回），右边「● 联机服务器 在线 / 离线」（真实探测 `wss://yunlan-mall-rooms…/health` 对应的 https 地址，超时算离线）+ 版本号（取打包时的提交短哈希或日期，不编造）。无边框、低对比度。
- 手机横屏：同一布局缩小；手机竖屏：Logo 在上，场景居中，菜单在下（参考 `phone-portrait-v2-logoB-r2-34.png`）。

## 6. 开场场景（画面）

照试做版的 4 个镜头和调色，正式版要补的（试做版暴露的弱点）：
- 远景楼：给 2–3 种楼做立面贴图（窗格、楼层带、随机亮灯，避免五颜六色像彩纸），加高度雾；不能再是光秃方块。
- 楼顶镜头：真正的沙袋模型（不是球）、景深虚化前景、重机枪在两次连射之间看得见、丧尸要有扑、踉跄的动作，数量更密。
- 直升机：机身剪影要像直升机（专门的低多边形模型或改造 `ride-vehicles.js` 的），旋翼模糊盘 + 下洗气流。
- 雨：在 2 倍像素密度下也看得见，地面有溅水；探照灯光柱和物体相交处要柔和。
- 镜头 2 的湿地面反光（只给这一镜加）。
- 后期：Bloom、ACES、青橙调色、色差、暗角、颗粒、2.39:1 黑边、白闪（试做版已有）。

复用（试做版已证明能单独引入）：`createRideVehicle`（ride-vehicles.js）、`buildTwinHmg`（twin-hmg.js）、`soldier.js` 的 `buildParts/RIG` + `rig-skin.js` + `squad.js` 的 `SQUAD` 外观、`zombie-skin.js` 的 `loadZombieKit`、`siege-props.js` 的火光与信号弹、`assets/models/fps/m4a1-mobile.glb`、`buildLayout()` 里的真实楼型（打包时导出成一份小 JSON，开场不要引入整个布局模块）。

## 7. 约束

- **加载预算**：进度条阶段目标总下载 ≤ 4 MB（gzip 后），手机中档机 ≤ 5 秒读完；开场期间显存 ≤ 150 MB。试做版是 7.6 MB 且丧尸贴图在主线程现画 6 秒——正式版必须把丧尸贴图在打包时预先画好（压缩贴图），不能在手机上现画。
- **帧率**：开场在中档手机上稳定 30 帧以上、电脑 60 帧；按画质档自动降：渲染分辨率、Bloom 分辨率、丧尸数量、雨量、景深开关。
- **释放**：进入游戏前开场场景必须彻底释放（`renderer.dispose()`、`forceContextLoss()`、贴图 / 几何体 dispose），游戏用自己的 GL 上下文。同一时间只有一个 WebGL 上下文。
- **两种打包都要能用**：`npm run build:netlify`（Cloudflare Pages，多文件，可按需加载）和 `npm run build`（`dist/mall.html` 单文件全内联）。开场代码要单独成块，Pages 版里不能把游戏本体拖进首页的首次下载。
- **后台预下载**：主菜单出现后才开始，只 `fetch` 进 HTTP 缓存（或 `<link rel="prefetch">`），不 `import`、不解析；省流量模式（`navigator.connection.saveData`）下不做。
- 现有测试 `tests/cover-options.test.js`、和封面相关的测试会随旧封面一起改写；`runtime.js` 的内存档位 / 启动标记（`markBootStart`、`armBootGuard`）流程不变。
- 字体：毛笔字（试做版用 Ma Shan Zheng，按需子集化，约 170 KB 全部字体）随网站一起打包，不在运行时连 Google Fonts。
- 代码注释、界面文字用中文，与仓库现有风格一致。
