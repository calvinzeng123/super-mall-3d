## 公共交通核与首层

标准层用 **3.2 米宽横向走廊**串联三户。两部电梯位于中南侧，井道中心相对楼栋为 `(−1.7, 5.1)`、`(1.7, 5.1)`，各 2.7 × 3 米、门朝北，门前有独立候梯区。东西两侧各有一部消防楼梯，与三户外墙及采光空隙分开。

楼梯间西侧范围为 `x=−20.4..−15、z=−12.5..−3.1`，东侧对称；模型和楼板保留真实梯井、双跑楼梯以及净深 1.8 米的入口平台。**楼梯仍通过门口互动换层**，可以走进入口平台，尚不能靠逐级行走连续跨层。玻璃电梯沿用连续开门、进舱、升降和出舱流程。

上部楼板由九块不重叠的板组成，按照三户、走廊、电梯与楼梯的实际位置搭建；三处采光空隙没有用矩形整板填满。电梯井和梯井均有逐层洞口，模型自带的两块结构楼板在运行时排除，由园区楼板统一承接。

1F 大堂重新布置入口门厅、礼宾接待、等候会客、信报快递、物业、社区阅读及卫生间七区。家具、分隔及可走通道取自同一份 `lobbyPlan`，其陈设参与碰撞。南侧主入口连接原地面人行路，入口坐标随新外包络更新至世界 `z=−201.4`。

B1 保留整层停车板及独立进出坡道。六米出口车道位于电梯东侧，局部 `x=5.5..11.5`，避免车道穿过双电梯；四栋地下支路与住宅共享干道随之移到各栋中心以东 8.5 米。R1 从核心筒至地下干道的起段为 `(49,−218) → (57.5,−218) → (57.5,−190) → (106.066,−190)`，接原 **二期 → 地铁 → 一期 → 酒店 → 公寓** 通道；连接 ID 保持不变。

## 模型、坐标与碰撞来源

源模型仍保存在 [`prototypes/residential01/`](../prototypes/residential01/)、[`residential02/`](../prototypes/residential02/) 与 [`residential03/`](../prototypes/residential03/)。本次接入不修改原 `.blend`、GLB 或独立 HTML；园区另行管理模型的楼层位置、显示、灯光和碰撞。独立查看器仍可自由穿墙，园区的人物碰撞不依赖它。

- `src/layout/residential-plan.js` 定义三个单元相对楼栋的 frame：01 `(−19.4,1.6,0°)`，02 `(3.8,1.6,0°)`，03 `(8.8,−1.6,180°)`。三者尺寸保持原值，包含阳台的深度均为 14.3 米。
- Blender 平面坐标转换为单元平面时采用 `x=X、z=11.5−Y`。GLB 已是米制、Y 向上，渲染只需局部 `[0,0,11.5]` 平移，再应用单元 frame 和楼层标高，不能再次转换 Blender 轴向。
- `scripts/prepare-residential-plans.py` 读取三套 `plan_XX.json` 与 `actual-mesh-audit.json`，从真实网格离地 0.12–1.75 米的障碍投影生成带洞多边形，进行几何并集和保留拓扑的 1 mm 简化。01/02/03 的 981/1023/1060 件实测障碍合并为 84/86/93 组多边形。
- 生成的 `src/layout/residential-plan-data.js` 纳入 Git，保存房间、入口、真实碰撞、实际路线及源文件 SHA256。导航对相同平面位置的楼层共享碰撞几何，避免为 29 个标准层重复复制。
- 室内通行以实测多边形为准；旧 JSON 中没有实际建出的 03 淋浴门不作为通行依据。七处真实淋浴开口由最终模型的固定玻璃与回边玻璃位置导出。

用户自制套房中的床组、沙发等继续保留原始比例和来源；用户模型及其图片不是 CC0。新增材质沿用仓库已有的 Poly Haven 免费材质，详情见[材质来源](texture-sources.md)、[01/02 源模型交付](residential-01-02-delivery.md)及[03 源模型交付](residential-prototype-delivery.md)。

## 离线加载与资源管理

`build.mjs` 将三个 GLB 分别 gzip 压缩并内嵌到生成的 `src/render/residential-data.js` 和离线页，浏览器通过 `DecompressionStream` 解压，无运行时远程模型地址。加载器依次解析三套模板，按材质和顶板显隐分组进行合批；共享几何与材质，图片按内容哈希和采样参数去重。移动端住宅贴图边长上限为 512，几何上传 GPU 后释放 CPU 顶点数组。

选中或进入楼层时实例化该层的三户，远层使用根据真实平面生成的外壳。酒店、公寓和住宅共用 **最多三层的 LRU 访问缓存**；退层仅释放该层实例与自有几何，共享源资源由加载器统一持有，不能随楼层一起销毁。

住宅灯池固定为桌面 12 盏、移动端 8 盏，进入住宅时跟随当前户，楼层总览时分配给三户；离开住宅层时隐藏。不为 348 户各自常驻完整灯组。酒店与公寓仍使用原有独立套房灯池。

主要职责：

| 文件 | 用途 |
|---|---|
| `src/layout/hospitality.js` | 楼层、三户、公共交通核、大堂、楼板与连接 |
| `src/layout/nav.js` | 实测多边形碰撞、大堂碰撞与公共路线 |
| `src/render/residential-asset.js` | 解压、共享模板、合批、贴图去重及资源所有权 |
| `src/render/build/residential-models.js` | 每层模型实例与顶板显隐 |
| `src/render/build/residential-shell.js` | 按实际平面生成外壳、大堂、公共区和屋顶 |
| `src/render/residential-lighting.js` | 住宅固定灯池 |
| `src/render/app.js` | 访问层缓存、远近层与剖切显示 |

可从 `window.__mall.residentialStats` 查看资源统计，从 `window.__mall.ctx.residentialLighting` 检查灯池；这些是诊断接口，不能代替实际浏览器验收。

## 重建与验证

普通源码修改不需要 Blender 或 Shapely，使用现有模型即可构建：

```sh
npm ci
npm test
npm run build
npm run serve
```

修改源模型后，先按照各样板交付文档重新构建并审计 GLB/Blender，再生成运行时计划：

```sh
uv run --with shapely scripts/prepare-residential-plans.py
npm test
npm run build
```

Shapely 仅是生成脚本依赖。`src/layout/residential-plan-data.js` 需要提交；`src/render/residential-data.js`、`pbr-data.js`、`suite-data.js` 是被忽略的构建产物，不能手改。发布文件是重新构建的 `dist/mall.html` 与 `dist/artifact.html`。

本轮 **102/102 自动化测试通过**，包括全部 748 个单元的入户/内门双向通行、三套实测模型的 46 条双向路线（含七处淋浴）、四栋大堂的七区可达、2F/30F 共 96 条公共路线、各层井道与平台、采光空隙及板块无重叠、四栋地库出入口、原地下连接链、400 套酒店公寓与 10 套首层复式。浏览器、离线加载和最终产物验证以[本轮 QA](qa-2026-10-09-residential-integration.md)为准。
