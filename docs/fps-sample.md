# 云澜汇手机 FPS 小样 · 2026-10-19

## 玩法与范围

`src/fps/mission-layout.js` 是任务、出生点、5 名敌人、队友、目标和战术物件的同源数据。任务从 P1-1F 出发，经 H-1F 实体消防梯到 H-2F，再通过 P1 的扶梯和地下公共走道到 A-B1。全程连续移动，不靠传送完成关卡。

导览保留 P1/H/A 的 53 个目录楼层和 400 套原客房；FPS 为 15 个可行走楼层、3 个封闭顶盖和 60 套客房。原上下两层地下连接、楼梯、门洞、套房碰撞继续工作。非本区域数据在创建渲染对象之前裁掉，FPS 上层楼层及不存在的连接一并移除，避免只隐藏网格却保留内存。

玩家有 SMG-45（25 发弹匣）与 Desert Eagle（7 发弹匣）、有限备弹及两个急救包。任务点恢复少量生命与备弹。前两个目标必须在范围内、视线无遮挡时完成读取；没有情报不能提前撤离。最后在公寓 B1 停留 8 秒，附近可见敌人会阻止撤离；离开区域重置计时。死亡或成功均进入结算，可重新开始。

## 移动与 AI

`pathfinding.js` 使用原 `nav.step` 验证直线段、楼梯和连廊。楼层内用缓存网格路径，楼层之间用真实门洞、坡面和楼梯连接。目标引导只能跳到经实际碰撞验证可达的后续点，避免只凭距离跳过楼梯入口。

回声支持跟随、守点、掩护与倒地救援。敌人沿可走路线巡逻，观察到目标或听到同层枪声后警戒；射击之前重复检查视线。不同导航楼层之间采取保守遮挡规则，不会隔着楼板开火。当前为本地 PvE 小样，没有多人服务器、排位系统或完整战利品经济。

## 手机输入与资源

封面保持二维，进入模式时动态 import 场景。FPS 模块再按需载入枪械 GLB，使用同一个 WebGLRenderer 的独立相机最后渲染手臂和枪。暂停菜单可调节控制布局和手感；横竖屏位置独立保存。暂停、后台和失焦会释放移动/开火状态。

地图使用流畅画质与 30 fps 上限；FPS 不建立导览人群、车辆、标签及动线。原套房按层缓存和共享材质继续使用。射线、示踪线对象重用；枪械顺序加载，纹理下采样和重复手部材质共享。

线上包不发布住宅 01/02/03 的模型数据；源文件仍保留。首次下载和 GPU 解码仍需一定时间，启动页会显示阶段进度。真实 iPhone 的设备性能需另做实测；浏览器模拟结果不应写成实体设备帧率。

## 可选模型 API

默认本地 AI 即可完成整局游戏，常见中文/英文指令先本地解析。未识别的自然语言可提交 `POST /.netlify/functions/squad-order`，请求体为 `{ "text": "队友指令" }`。

若站点所有者以后启用模型，需要在 Netlify 服务端设置：

- `FPS_MODEL_ENABLED=true`
- `FPS_MODEL_BASE_URL`：兼容 Chat Completions 的 HTTPS 基础地址，通常以 `/v1/` 结束。
- `FPS_MODEL_NAME`：模型名称。
- `FPS_MODEL_API_KEY`：只放在服务端环境变量。

服务端仅允许输出 `follow`、`hold`、`cover`，不把输出作为代码执行；输入最多 160 字，服务端超时 5 秒。缺少配置返回 503，客户端继续使用三个本地指令。模型不决定命中、伤害、弹药、位置、任务完成或胜负，API Key 不进入静态包。当前交付不要求用户提供密钥。
