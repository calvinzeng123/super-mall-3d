# 住宅 03 四房两厅原型

> 当前状态（2026-10-09）：三套模型已接入 R1–R4，四栋合计 348 户，1F 独立大堂。本文记录独立模型的原始朝向与规划；03 在园区标准层旋转 180°，方位应按[住宅接入说明](residential-integration.md)转换。最终园区验证见[接入 QA](qa-2026-10-09-residential-integration.md)。

03 先作为独立 Blender 样板验证：四间卧室分置四个外角，客厅面向模型南侧通长阳台，餐厅与玄关在中部连接两侧卧室和厨房。所有卧室均从公共区域进入；主卧与南次卧各有套卫，北侧两间卧室共用玄关旁的公卫。独立原型阶段未改园区、楼层、户号或住宅统计；后续接入已完成。

平面数据见 [plan_03.json](../scripts/residential/plan_03.json)。建模使用米制坐标：X 向东、Y 向北、Z 向上，原点位于室内外包络的西南外角。墙体的 `a/b` 为中心线，门窗的 `at` 为从 `a` 沿墙方向量取的距离。

## 通行、门窗与家具

入户门规划宽 1.10 米；卧室门宽 0.90–0.95 米，洗衣门 0.85 米，厨房侧移门 1.40 米。客厅阳台门总玻璃洞宽 6.00 米，两端停放门扇，实际通行段为中间 **3.00 米**。验证与建模均应使用 `clear_intervals`，不能把整个玻璃洞当作可穿越空间。

两侧家庭厅廊墙间规划净宽 1.48 米。所有四间卧室有两侧外窗；通高柜放在实墙旁，低书桌低于对应 0.85 米窗台。主卧西窗缩为全局 y=0.60–2.00 米，避开源床床头。主卧门向南开启，打开后的门叶位于 x=3.41，避免穿入主卫隔墙。

实际建模复核后，公卫与洗衣房北窗均改为 2.20–2.60 米高的采光窗，避开镜柜、叠放洗烘设备与上部收纳。公卫石材贴面需按该窗洞裁开；厨房窗下仅保留低挡水边，不能用整片高背板覆盖玻璃。厨房北窗的全局横向范围调整为 x=5.20–7.00 米，让西侧吊柜与窗侧边分开。

主卧使用来源模型的完整床组，**保持 1:1 比例**。床单体规划尺寸为 2.22857 × 2.18489 米，中心为 (1.45, 3.65)，绕 Z 轴旋转 90°、床头朝西。床组还包括原床头板和两只床头柜，不另建重复床头柜。整组保留范围 x≈0.26–3.15、y≈1.90–5.40 米，其中地毯可踩踏，不作为通行障碍。

`collision_rects` 单独记录床、床头板和两只床头柜的实体预留，主卧通路在其东侧。它们是从来源尺寸建立的规划占地；包围矩形之间的交叠不等同于源网格相穿，也不代表最终网格已经通过检查。其余三间卧室使用按房间设计的新建精细次卧床，不能把这套大床整体缩小后塞入次卧。

客厅电视柜、厨房操作台、玄关储物、衣柜和卫浴设备都有明确占地，模型已包含柜门分缝、台面收口、踢脚、把手、软包、布料褶皱和灯具。家具数据用于建立初始空间关系；最终资产以实际网格核验为准。

## 平面复核

规划检查将 0.30 米半径的行走圆盘沿路线每 0.03 米采样，计算其到墙体、打开门叶、淋浴玻璃及家具预留矩形的距离。窗洞仍作为不可通行墙段，阳台门仅使用明确的开启净段。八条路线均通过 0.30 米中心净距门槛：

| 路线 | 最小中心至障碍距离（米） |
| --- | ---: |
| 入户—客厅—阳台 | 0.450 |
| 公共区—主卧—主卫淋浴 | 0.330 |
| 公共区—西北次卧 | 0.415 |
| 公共区—东北次卧 | 0.390 |
| 公共区—南次卧—套卫淋浴 | 0.350 |
| 玄关—厨房 | 0.510 |
| 玄关—公卫淋浴 | 0.330 |
| 玄关—洗衣房 | 0.320 |

该结果说明所列规划路线没有被占地阻断，不等同于法规合规、无障碍通行认证或实际 Blender 网格验收。两条较紧的局部路线为洗衣房门前和主卧门口；后续增加线脚、门套、窗帘或家具细节时，应保留其净距并再次检查。餐椅当前处于规划使用位置，拉椅动作需要在模型中进一步验证。

14 个室内分区总面积为 202.40 平方米且互不重叠；门和开放连接构成的图可从入户到达每个房间。四个卧室各有两面外窗。家具与墙/打开门叶的规划占地交叠检查已排除南次卧台盆进入东外墙的问题。

## 实际模型核验与中文平面图

[audit_residence.py](../scripts/residential/audit_residence.py) 独立打开保存后的 `.blend`，读取经修改器求值后的网格与世界变换；它不会执行重建脚本，也不会覆盖模型。家具和墙的交叠先经过世界包围盒筛选，再用实际三角面或包含关系确认，墙角小于等于 0.03 米的接触单独容许。

通行检查将每件真实网格截取到离地 0.12–1.75 米，投影为保守轮廓，以 0.30 米行走半径扩张后，在 0.05 米网格上搜索从入户至各房间、阳台和实际淋浴底盘的路线。地毯、地垫、窗帘和顶灯不计入行走障碍。若物体含凹形或彼此分离的部件，凸包可能偏保守，因此失败项需回到模型判断，不能直接宣布房间不可达。

审计同时记录门口家具侵入、窗前高柜候选和每件物体的真实包围盒；JSON 只提供房间命名与开口意图，不用于替代实际家具尺寸。输出 `actual-mesh-audit.json` 是每次运行的证据，需核对其 `source_blend` 与 `blend_mtime` 对应最终模型。

2026-10-07 的修正版实测包含 **1705 个网格对象、1023 个家具部件**。在上述容差与行走半径下，确认墙体穿插 **0**、门洞家具侵入 **0**、窗前高柜或贴面遮挡候选 **0**；15 个房间/阳台目标与 3 个实际淋浴底盘，共 **18/18 个目标可从入户到达**。这是实际模型的几何检查，不是前述 JSON 规划检查的重复引用。

该轮修正把南次卧床向南移至 y=1.10 米，释放床北侧至套卫转角的路线；南套卫和公卫按外墙内表面缩减家具模块，解决台盆、淋浴构件伸入外墙的问题。最终家具位置可能与初始 JSON 占地预留不同，应以 `.blend`、实际审计报告和由其生成的平面图为准。

[draw_plan.py](../scripts/residential/draw_plan.py) 读取该审计报告，把实际墙体和家具投影到中文户型图，生成 `03四房两厅_中文平面图.svg` 与 PNG。面积标注仍来自含墙平面分区，不因为完成了网格检查而变成净使用面积。

```sh
/Applications/Blender.app/Contents/MacOS/Blender --background \
  --python scripts/residential/audit_residence.py -- \
  --blend "/绝对路径/云澜汇_03四房两厅.blend" --out "/绝对路径/输出目录"
python3 scripts/residential/draw_plan.py \
  --audit "/绝对路径/输出目录/actual-mesh-audit.json" --out "/绝对路径/输出目录"
```
