# FPS 扩展验收 · 2026-10-20

本页记录本轮源码的功能验证，不代替发布记录或真实 iPhone 性能实测。开发页为 `http://127.0.0.1:5176/`；浏览器使用 Playwright CLI 的独立 `fps-expansion` 会话。

## 地图与自动测试

以下 35 项测试在最终导航修复后全部通过：

```sh
node --test tests/fps-rules.test.js tests/fps-hud.test.js \
  tests/fps-mobility.test.js tests/fps-tactics.test.js \
  tests/fps-follow.test.js tests/playable.test.js
```

覆盖内容：

- 普通探索直接使用完整 `buildLayout()`，恢复全部期数、住宅、地铁、云环桥和周边地块；不设置会触发精简渲染的 `layout.playable`。
- FPS 在创建场景之前裁剪为一期、酒店、公寓。18 个场景楼层中 17 个可行走；酒店、公寓 RF 保留真实楼梯及电梯停靠，一期 RF 保持封闭顶盖。
- 两份情报、地下接应车和屋顶直升机之间均存在双向连续步行路线；车辆实体碰撞不会封住登车区域。
- 回声在 20、30、60 fps 模拟步进下沿真实路线跟随；不会跳过楼梯入口。
- 跳跃重力、落地、低顶限制、禁止二连跳；冲刺速度、耐力、持枪姿态；腾空仍不能穿过战术掩体。
- 敌人视野角、距离、同层视线、枪声调查、装甲与头部伤害、移动目标命中率；有墙遮挡的声音不会授权射击。
- 有限弹药、换弹、切枪、暂停、医疗消耗、任务顺序和争夺中的撤离计时。

整局复跑发现酒店东消防梯第一阶的斜向入口问题：人物已经从侧面进入起步段，但仍留在普通楼面状态。共用 `nav.step` 已增加仅限坡道两端的近距离捕获，并另加上下行及禁止中段吸附的回归测试。

同时修复扶梯护栏附近的提示点恢复：触屏转向与渲染更新频率不同，人物可能偏到护栏侧边；现在会返回最后一个真实可达的拐点继续引导，不改变碰撞或传送人物。新增回归使用浏览器实测卡点，并模拟转向每两帧更新。

## 实际浏览器通关

自动控制器只调用玩家原有的 `input`、`look`、`action`，读取 HUD 的真实路线点进行移动、瞄准、开火及互动。没有改写角色坐标、生命、任务阶段、敌人生命或结果。控制器会精确瞄准，所以通关命中率不代表普通玩家的难度。

| 路线 | 结果 | 情报 | 队友 | 证据 |
| --- | --- | --- | --- | --- |
| 酒店 RF 直升机 | 59 秒；4 击杀；11 发射击；成功 | 2/2 | 存活 | [逐段采样](qa/fps-expansion-helicopter.json) |
| 公寓 B1 接应车 | 177 秒，含途中静止拍摄；5 击杀；13 发射击；成功 | 2/2 | 存活 | [逐段采样](qa/fps-expansion-car.json) |

直升机任务采样无异常。完成 11 秒守点后，模型旋翼旋转并升空，角色经历 4.2 秒第一人称登机、离场过程，最后相机高度为 25.98m，超过 13.3m 的酒店屋顶。截图：`output/playwright/fps-helicopter-extraction-result.png`。

车辆路线在上述两处导航修复后重载页面重新完成，任务采样无异常。沿酒店消防梯、一期扶梯及地下公共通道进入公寓 B1，守点 8 秒后进入接应车并离场，最后相机位于 `(-40.57, -2.78, -214.35)`。截图：`output/playwright/fps-car-boarding-area.png`、`output/playwright/fps-car-extraction-result.png`。

## 电梯与移动动画

从酒店 2F 任务走廊实际走到 `H-L1` 候梯点，打开楼层菜单并点击 B2。99 个采样记录到完整的“走向电梯 → 进入轿厢 → 关门 → 下行 → 开门 → 到达”。玩家连续从 6.5m 降到 -8.4m；附近回声进入同一轿厢并在 B2 到达。过程不使用坐标传送或黑场。见 [电梯采样](qa/fps-expansion-elevator.json) 与 `output/playwright/fps-elevator-descending.png`。

真实枪械与贴图手臂在冲刺时低持、倾斜并增加步态摆动，停跑后回正。在普通移动输入下，跳跃采样最高 0.745m，经历上升、下降、正常落地；视角和手臂同时响应。见 [移动采样](qa/fps-expansion-motion.json)、`output/playwright/fps-sprint-landscape.png` 与 `output/playwright/fps-jump-landscape.png`。

## 手机控件

完整游戏内将按键大小设为 140%，逐一验证以下 CSS 视口：

| 竖屏 | 横屏 |
| --- | --- |
| 375 × 667 | 667 × 375 |
| 393 × 852 | 852 × 393 |
| 430 × 932 | 932 × 430 |

所有默认操作按钮均不越界、不小于 44px；包含摇杆、冲刺、跳跃、队友指令、暂停和撤离切换的所有矩形范围互不重叠；启用按钮的中心命中测试全部通过。见 [按键范围与命中记录](qa/fps-expansion-mobile.json)。截图保存为 `output/playwright/fps-controls-<宽>x<高>-140.png`。

使用真实指针拖动跳跃按钮并保存，确认编辑过程不触发射击、只改变竖屏布局，横屏保持独立位置；刷新页面、重新进入 FPS 后仍恢复所保存位置。见 [布局持久化记录](qa/fps-expansion-persistence.json)。测试结束后通过界面的“恢复默认操作设置”清除了测试位置。

## 验收边界与素材

- 以上是桌面浏览器中的实际游戏验证及手机尺寸模拟，尚未测量实体 iPhone 的帧率、发热、内存峰值或持续游玩。
- 跳跃使用当前楼层的碰撞和支撑，不包含攀爬、翻越栏杆或坠入深井；不同导航楼层之间不互相射击。
