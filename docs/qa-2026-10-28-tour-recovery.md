## 本次故障判断

用户报告：封面可以打开，点击“完整园区探索”后浏览器提示网页无法打开。

现场核对首页 HTTP 200，Netlify 站点为 `current`、已发布部署为 `ready`，没有部署错误。旧版 WebKit 手机模拟也能最终进入；因此没有复现实体手机的网页进程崩溃，不能把推测写成已确认的设备日志结论。

但发现与症状吻合的启动内存风险：

1. 首屏尚未进入任何房间，就下载并解析套房和全部三套住宅。住宅模板额外保留 71,668,220 字节 CPU 几何；这些下载合计约 37.9 MB。
2. 手机招牌图集先生成大画布再缩小，但中间大画布未显式释放。24 张原始图集的 RGBA 后备缓冲总计 195,035,136 字节，约 186 MiB，依赖浏览器延后回收。
3. 所有批次在最终整理时复制顶点缓冲，使构建器容量与最终几何同时存在，增加瞬时峰值。

这轮按已确认的分配问题修复，不以删掉其它期或精装户型作为处理方式。

## 修复内容

- 完整地图和外壳保持。在线导览首屏不下载套房和住宅模型；首次选中/进入对应客房层时才载入，并显示加载提示。
- 两类精装模型串行解码；失败保留园区和外壳，提供重试按钮。切走楼层后，异步完成不会重新生成已离开的楼层。
- 缩图复制后立即将临时源画布缩至 1×1，最终贴图像素保持一致。
- 批次 flush 使用独占缓冲转移，支持时调用 `transferToFixedLength`，旧浏览器回退复制并释放构建器引用；直接 `mesh()` 仍保留独立快照语义。
- 手机最终整理楼层时分批让出主线程。FPS 保持原套房预载，不改变战斗地图和任务。

离线 HTML 仍内嵌完整模型，不等同于在线按需下载的体积优化。
